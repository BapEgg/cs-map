## 개념

한 번 작성하면 **어느 컴퓨터에서든 같게 돌도록** 만든 언어와 실행 환경이다. 소스를 바이트코드로 바꾸고, 각 컴퓨터의 JVM이 그걸 실행한다.
객체 지향, 자동 메모리 관리(GC), 풍부한 라이브러리가 특징이라 서버 개발에 널리 쓰인다.

## 왜 나왔나

C·C++은 컴파일한 기계어가 CPU·운영체제마다 달라 같은 프로그램을 플랫폼마다 다시 빌드해야 했고, 메모리를 직접 해제하다 생기는 버그가 잦았다. 자바는 중간 언어(바이트코드)와 그것을 돌리는 가상 머신(JVM)을 두어 "한 번 컴파일하면 어디서든", 그리고 GC로 메모리 해제를 런타임에 맡겨 그 두 문제를 풀었다. 서버가 오래 돌고 스레드를 많이 쓰는 환경에서 JVM의 JIT·GC·스레드 모델이 잘 맞아 백엔드의 주류가 됐다.

이 과목의 값어치는 **CS 기초와 이어 붙는 데** 있다.
JVM 메모리 구조는 운영체제의 메모리 영역과, GC는 페이지 교체 기법과,
스레드 풀은 프로세스·스레드와 같은 이야기다. (HANDOFF 5-6)

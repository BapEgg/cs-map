## 왜 나왔나

**필요한 페이지만 메모리에 올리고** 나머지는 디스크에 두면, 물리 메모리보다 큰 프로그램도 실행할 수 있다.

## 심화

### 내부 구조

- 요구 페이징: 프로그램 전체가 아니라 실제로 접근한 페이지만 메모리에 올린다.
- 페이지 폴트 처리: 접근한 페이지가 메모리에 없음 → 트랩 발생 → 운영체제가 디스크에서 읽어 빈 프레임에 올림 → 페이지 테이블 갱신 → 멈췄던 명령어를 다시 실행.
- 메모리는 부족한데 실행 중인 프로세스가 너무 많으면, 페이지를 넣고 빼는 데만 시간을 쓰는 스래싱(thrashing)이 생긴다.

### 실제 활용

- fork()로 프로세스를 복제해도 메모리가 바로 두 배가 되지 않는 이유: 쓰기 전까지 같은 페이지를 공유하는 Copy-on-Write 덕분이다.
- 파일을 메모리처럼 다루는 mmap, 리눅스의 swap 영역이 모두 가상 메모리 위에서 동작한다.

### 면접 질문

#### 스래싱이란 무엇이고 어떻게 해결하나요?

프로세스들이 자주 쓰는 페이지 묶음(워킹셋)을 메모리에 다 올릴 수 없어 페이지 폴트가 폭증하고, CPU가 일은 못 하고 페이지 교체만 하는 상태입니다. 동시에 실행하는 프로세스 수를 줄이거나, 워킹셋 모델·페이지 폴트 빈도(PFF)로 프로세스별 프레임 수를 조절해 해결합니다.

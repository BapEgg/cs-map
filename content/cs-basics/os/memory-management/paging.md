## 개념

메모리를 **같은 크기의 칸(페이지)**으로 자르고, 프로그램도 같은 크기로 잘라 빈 칸 아무 데나 넣는다.
어느 조각이 어느 칸에 있는지는 페이지 테이블이 기억하고, 주소 변환은 MMU가 한다. 크기가 같으니 빈칸이 어디든 들어가 자리 낭비가 없다.

## 왜 나왔나

**크기를 고정하면** 어떤 빈칸에든 넣을 수 있어 외부 단편화가 사라진다. 주소 변환은 MMU와 페이지 테이블이 맡는다.

## 심화

### 내부 구조

- 가상 주소를 페이지 번호(p)와 오프셋(d)으로 나눈다. MMU가 페이지 테이블에서 p를 물리 프레임 번호(f)로 바꾸고, f와 d를 합쳐 실제 주소를 만든다.
- 페이지 테이블도 메모리에 있어서 매번 메모리를 두 번 읽게 된다. 그래서 최근 변환 결과를 담는 전용 캐시인 TLB를 둔다.
- 주소 공간이 크면 페이지 테이블이 거대해져서, 필요한 부분만 만드는 다단계 페이지 테이블을 쓴다(x86-64는 보통 4단계).
- 크기가 고정이라 외부 단편화는 없지만, 마지막 페이지의 남는 공간(내부 단편화)은 생긴다.

### 실제 활용

- 일반적인 페이지 크기는 4KB. 데이터베이스나 JVM처럼 메모리를 크게 쓰는 프로그램은 2MB·1GB 대용량 페이지(Huge Pages)로 TLB 미스를 줄인다.

### 면접 질문

#### 페이징과 세그멘테이션의 차이는 무엇인가요?

페이징은 메모리를 같은 크기로 나눠 외부 단편화를 없애지만 내부 단편화가 생길 수 있고, 세그멘테이션은 코드·데이터·스택 같은 의미 단위로 나눠 보호·공유가 쉽지만 크기가 달라 외부 단편화가 생깁니다.

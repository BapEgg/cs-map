## 개념

"합이 k인 연속 구간", "서로 다른 문자가 m개 이하인 가장 긴 부분 문자열", "정렬된 배열에서 두 수의 합이 target인 쌍" — 전부 구간(또는 쌍)을 다루고, 순진하게 짜면 시작·끝을 이중 반복문으로 돌려 O(n²)이다. 세 기법은 **한 번 훑기(O(n))** 로 바꾼다.

**투 포인터**: 인덱스 둘(`l`, `r`)을 두고 조건에 따라 한쪽씩 **앞으로만** 움직인다. 정렬된 배열에서 두 수의 합이면 양 끝에서 시작해 합이 크면 `r--`, 작으면 `l++`. **슬라이딩 윈도우**: 투 포인터의 특수형으로 `[l, r]` 구간을 유지하며 `r`을 밀어 넣고 조건이 깨지면 `l`을 밀어 뺀다 — 구간의 합·개수·집합을 넣고 뺄 때 O(1)로 갱신한다. **누적 합**: `prefix[i] = a[0] + … + a[i-1]`을 미리 만들어 두면 구간 `[l, r]`의 합은 `prefix[r+1] - prefix[l]`, O(1). 구간 질의가 여러 번 올 때 쓴다.

#### 예시 — 합이 k 이상인 가장 짧은 구간(양수 배열)

```java
int shortest(int[] a, int k) {
    int l = 0, sum = 0, best = Integer.MAX_VALUE;
    for (int r = 0; r < a.length; r++) {
        sum += a[r];                                  // r을 밀어 넣는다
        while (sum >= k) {                            // 조건을 만족하면
            best = Math.min(best, r - l + 1);
            sum -= a[l++];                            // l을 밀어 뺀다
        }
    }
    return best == Integer.MAX_VALUE ? 0 : best;
}
```

#### 작동 과정 — `[2, 3, 1, 2, 4, 3]`, k = 7에서 창이 움직이는 모습

- r=0..3: 합 2, 5, 6, 8. 8 ≥ 7 → 길이 4 기록 → l을 밀어 2를 뺌(합 6) → 조건 깨짐, 멈춤.
- r=4: 합 10 ≥ 7 → 길이 4 → 3 뺌(7) → 길이 3 기록 → 1 뺌(6) → 멈춤.
- r=5: 합 9 → 길이 3 → 2 뺌(7) → 길이 2 기록(`[4,3]`) → 4 뺌(3) → 멈춤.
- 결과: 답 2. `l`과 `r`은 각각 최대 n번 움직이므로 전체 O(n). 이중 반복문이면 O(n²)에 같은 답. 되는 이유는 **양수라서** r을 밀면 합이 늘고 l을 밀면 줄어드는 단조성이 있기 때문 — 음수가 섞이면 이 논리가 깨진다.

#### 비교 — 세 기법은 언제 무엇을

| 기법 | 문제 모양 | 전제 | 복잡도 |
|---|---|---|---|
| 투 포인터(양 끝) | 정렬된 배열의 쌍·합 | 정렬됨(움직일 방향이 정해짐) | O(n) (+정렬 O(n log n)) |
| 슬라이딩 윈도우 | 조건을 만족하는 연속 구간의 최장·최단·개수 | 구간을 늘리면/줄이면 조건이 한 방향으로 변함(단조성) | O(n) |
| 누적 합 | 구간 합 질의가 여러 번, 또는 "합이 정확히 k인 구간 개수" | 없음(음수 가능) | 전처리 O(n), 질의 O(1) |
| 누적 합 + 해시 | 합이 정확히 k인 구간(음수 포함) | `prefix[r] - prefix[l] = k` → `prefix[l]`을 해시로 조회 | O(n) |

## 왜 나왔나

이중 반복문은 같은 원소를 반복해서 다시 센다 — `[l, r]`의 합과 `[l, r+1]`의 합은 원소 하나 차이인데 처음부터 다시 더한다. "이전 계산에서 바뀐 부분만 갱신한다"는 발상이 슬라이딩 윈도우이고, "부분 합을 미리 적어 두면 차로 구한다"는 발상이 누적 합이다(적분과 미분의 관계). 정렬된 배열에서 양 끝 포인터를 좁히는 2-SUM은 O(n²) → O(n)의 고전이고, 3-SUM은 정렬 + 투 포인터로 O(n²)이 된다. 코딩 테스트에서 n = 10⁵~10⁶일 때 O(n²)를 O(n)·O(n log n)으로 내리는 첫 번째 도구다.

## 확인 질문

- 설명해 보기: 슬라이딩 윈도우가 O(n)인 이유는?
  답: `l`과 `r`이 각각 앞으로만 최대 n번 움직이고, 한 칸 움직일 때 넣고 빼는 갱신이 O(1)이므로 전체 2n번의 O(1) 작업.
- 다음 상태 예측: 음수가 섞인 배열에서 "합이 k 이상인 최단 구간"을 위 윈도우로 풀면?
  답: 틀릴 수 있다. `r`을 밀어 음수를 넣으면 합이 줄어 "조건이 깨졌으니 l을 밀지 말자"는 판단이 성립하지 않는다. 누적 합 + 단조 덱(monotonic deque)으로 O(n)에 푼다.
- 다음 상태 예측: 길이 10⁵ 배열에 구간 합 질의가 10⁵개 오면 누적 합 없이는?
  답: 질의마다 O(n)이면 10¹⁰ 연산. 누적 합으로 전처리 O(n) + 질의 O(1) → 2×10⁵.

## 심화

### 투 포인터의 두 형태

**양 끝에서 좁히기**: 정렬된 배열에서 `a[l] + a[r]`을 target과 비교해 한쪽을 움직인다. 정렬이 "어느 쪽을 움직여야 하나"를 정해 준다. 3-SUM은 첫 수를 고정하고 나머지에 이 방법(O(n²)). **같은 방향으로**: 두 정렬 배열의 병합·교집합, 중복 제거, 느린/빠른 포인터(연결 리스트 사이클 검출).

### 윈도우 안의 상태 유지

합·개수는 변수 하나. "서로 다른 문자 수"는 `Map<Char, Integer>`로 넣을 때 +1, 뺄 때 −1, 0이 되면 제거. "최댓값"은 단조 덱(앞은 최대, 뒤에서 작은 것을 밀어냄). 고정 길이 윈도우(길이 k의 구간 최대 합)는 `r`이 k−1을 넘을 때마다 `l`을 정확히 하나 민다.

### 누적 합의 확장

2차원(`P[i][j]` = 왼쪽 위 직사각형 합, 부분 직사각형은 포함-배제로 4항), 개수 누적(조건을 만족하는 원소 수), 차분 배열(구간에 값을 더하는 갱신을 O(1)에 기록하고 마지막에 누적 — 누적 합의 역). 갱신과 질의가 섞이면 누적 합은 못 쓰고 펜윅 트리·세그먼트 트리로 O(log n).

### 코딩 테스트에서

"연속 부분 배열/부분 문자열" + "최장·최단·개수·합" → 윈도우/누적 합. "정렬된" + "두 수/쌍" → 투 포인터. 윈도우가 안 되는 조건(음수, 조건이 비단조)이면 누적 합 + 해시(정확히 k)나 단조 덱. 자바에서는 합이 `int`를 넘는지(`long`) 먼저 본다. 인덱스 경계(`prefix` 길이 n+1)가 흔한 실수.

### 실무에서는

- 시계열의 이동 평균·이동 합(최근 5분 요청 수, 요청 제한의 슬라이딩 윈도우 카운터)이 그대로 윈도우다.
- 로그·지표의 "구간 합계"는 누적 합(또는 DB의 윈도우 함수 `SUM() OVER`)이다.
- 두 정렬된 목록의 병합·차이(동기화, diff)는 같은 방향 투 포인터.

### 면접 질문

#### 투 포인터와 슬라이딩 윈도우는 무엇이고, 언제 쓸 수 있나요?

두 인덱스를 한 방향으로만 움직이며 구간이나 쌍을 O(n)에 훑는 기법으로, 투 포인터는 정렬된 배열에서 양 끝을 좁히거나 두 배열을 같은 방향으로 병합할 때, 슬라이딩 윈도우는 조건을 만족하는 연속 구간의 최장·최단·개수를 구할 때 씁니다. 쓸 수 있는 조건은 단조성 — 구간을 늘리면 조건이 한 방향으로만 변하고 줄이면 반대로 변해야 "어느 포인터를 움직일지"가 정해집니다.
이중 반복문이 같은 원소를 반복해 세는 것을, 한 칸 이동 때 바뀐 원소만 넣고 빼서 없앤 것입니다.
예를 들어 양수 배열에서 합이 k 이상인 최단 구간은 `r`을 밀어 넣고 조건을 만족하는 동안 `l`을 밀어 빼며 O(n)에 풉니다. 한계는 음수가 섞이면 단조성이 깨져 윈도우가 틀리므로 누적 합 + 해시나 단조 덱이 필요하고, 정렬이 전제인 투 포인터는 정렬 비용 O(n log n)이 든다는 점입니다.

- 오답: "슬라이딩 윈도우는 창 크기가 고정이다" — 고정 길이는 특수형이고, 대개 조건에 따라 늘었다 줄어드는 가변 창이다.

#### 길이 10⁶ 배열에 구간 합 질의가 10⁶개 옵니다. 갱신도 섞여 있다면?

질의만 있으면 누적 합을 O(n)에 만들어 두고 각 질의를 `prefix[r+1] - prefix[l]`로 O(1)에 답합니다. 갱신(원소 값 변경)이 섞이면 누적 합은 갱신마다 O(n)이 들어 못 쓰고, 펜윅 트리(BIT)나 세그먼트 트리로 갱신·질의 모두 O(log n)에 처리합니다.
누적 합은 "미리 다 더해 둔다"라 값이 바뀌면 그 뒤의 모든 누적값이 바뀌기 때문이고, 트리 구조는 구간을 log n개의 덩어리로 나눠 덩어리 합만 고치기 때문입니다.
예를 들어 질의 10⁶ × O(1)은 즉시, 갱신·질의 섞인 10⁶ × O(log n) ≈ 2×10⁷도 충분합니다. 한계는 구간에 값을 더하는 "구간 갱신"이 오면 차분 배열(질의가 마지막에만) 또는 느린 전파(lazy propagation) 세그먼트 트리가 필요하고, 자바에서는 합의 범위를 `long`으로 잡아야 한다는 점입니다.

- 오답: "갱신이 있어도 누적 합을 그때그때 다시 만들면 된다" — 갱신마다 O(n)이라 10⁶ × 10⁶이다.

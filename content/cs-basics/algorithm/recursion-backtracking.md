## 개념

**재귀**는 함수가 자기 자신을 부르는 것이다. 성립하려면 둘이 필요하다 — 더 작은 입력으로 자신을 부르는 **재귀 단계**와, 더 줄일 수 없을 때 답을 바로 내는 **종료 조건**. `sum(n) = n + sum(n-1)`, `sum(0) = 0`. 호출마다 스택 프레임이 쌓이므로(스택 장) 깊이가 수만이면 `StackOverflowError`가 난다. 트리·그래프·"경우의 수"처럼 구조 자체가 재귀적인 문제에서 반복문보다 훨씬 짧게 써진다.

**백트래킹**은 재귀로 **선택지를 하나씩 시도**하는 방법이다. 한 칸을 고르고(선택), 다음 칸으로 재귀하고(탐색), 돌아오면 그 선택을 취소해(되돌리기) 다음 선택지를 시도한다. 모든 경우를 다 보면 지수 시간이므로, "이 길은 답이 될 수 없다"를 일찍 판단해 들어가지 않는 **가지치기**가 핵심이다. 순열·조합·부분집합·N-Queen·스도쿠·경로 찾기가 전부 이 틀이다.

#### 예시 — 순열: 선택 → 재귀 → 되돌리기

```java
void permute(int[] nums, boolean[] used, List<Integer> path, List<List<Integer>> out) {
    if (path.size() == nums.length) {      // 종료 조건: 다 골랐다
        out.add(new ArrayList<>(path));
        return;
    }
    for (int i = 0; i < nums.length; i++) {
        if (used[i]) continue;             // 가지치기: 이미 쓴 것
        used[i] = true;  path.add(nums[i]);       // 선택
        permute(nums, used, path, out);           // 재귀
        path.remove(path.size() - 1);  used[i] = false;  // 되돌리기
    }
}
```

#### 작동 과정 — `[1, 2, 3]`에서 호출 스택이 움직이는 순서

- `permute([])` → i=0 선택 → `permute([1])` → i=1 선택 → `permute([1,2])` → i=2 선택 → `permute([1,2,3])` → 종료 조건, 답 기록.
- 되돌아옴: `[1,2]`에서 3을 빼고 `used[2]=false`. 반복문 끝 → `[1]`로 돌아가 2를 빼고 → i=2 선택 → `permute([1,3])` → … `[1,3,2]` 기록.
- `[1]`의 반복문 끝 → `[]`로 돌아가 1을 빼고 → i=1 선택 → `permute([2])` → …
- 결과: 깊이 3의 재귀가 3! = 6개의 답을 순서대로 낸다. 되돌리기를 빠뜨리면 `[1,2,3]` 뒤에 `path`에 3이 남아 다음 답이 `[1,2,3,3,…]`처럼 오염된다.

#### 비교 — 재귀와 반복, 백트래킹과 완전 탐색

| | 재귀 | 반복문 + 스택 |
|---|---|---|
| 코드 | 구조가 문제와 닮아 짧음 | 길지만 깊이 제한 없음 |
| 메모리 | 호출 스택(깊이 × 프레임) | 내가 만든 스택(힙) |
| 위험 | 깊으면 `StackOverflowError`(자바 기본 수천~수만) | 없음 |
| 바꾸기 | 꼬리 재귀는 반복으로, 나머지는 명시적 스택으로 | |

백트래킹은 완전 탐색(모든 경우 생성)에 "중간에 포기"를 더한 것이다. 가지치기가 없으면 둘은 같다.

## 왜 나왔나

"n개 중 k개를 고르는 모든 경우"를 반복문으로 쓰려면 k겹 `for`가 필요하고 k가 변수면 쓸 수 없다. 재귀는 "하나 고르고 나머지는 같은 문제"로 k를 깊이로 바꿔 준다. 백트래킹은 1950년대 조합 탐색에서 이름이 붙었고, 제약 충족 문제(스도쿠, 배치, 스케줄링)의 표준 틀이 됐다. 모든 경우를 보는 것은 지수 시간이지만 실제 문제는 대부분의 가지가 일찍 죽으므로, 가지치기가 좋으면 실용적이다.

## 확인 질문

- 설명해 보기: 재귀 함수에 반드시 있어야 하는 두 부분은?
  답: 종료 조건(더 줄일 수 없을 때 바로 답)과, 더 작은 입력으로 자기를 부르는 재귀 단계. 종료 조건이 없거나 입력이 줄지 않으면 무한 재귀.
- 다음 상태 예측: 위 `permute`에서 `path.remove(...)`를 빠뜨리면?
  답: 첫 답 `[1,2,3]` 뒤에도 `path`가 비워지지 않아 다음 시도가 `[1,2,3,…]` 위에 쌓인다. 종료 조건 `size == nums.length`는 다시는 정확히 맞지 않아 답이 안 나오거나 잘못된 답이 나온다.
- 다음 상태 예측: 깊이 10만의 재귀(연결 리스트 순회)를 자바에서 돌리면?
  답: 기본 스레드 스택(보통 512KB~1MB)에서 `StackOverflowError`. 반복문으로 바꾸거나 명시적 스택을 쓴다.

## 심화

### 재귀 설계의 순서

1. 상태를 정한다 — 함수 매개변수가 "지금 어디까지 왔나"를 전부 담아야 한다(순열이면 `path`, `used`).
2. 종료 조건을 먼저 쓴다.
3. 한 단계에서 할 수 있는 선택을 나열하고, 선택마다 상태를 바꿔 재귀한 뒤 되돌린다.
4. 가지치기를 넣는다 — 합이 이미 목표를 넘음, 남은 개수로는 부족함, 중복 순서(조합이면 `start` 인덱스로 오름차순만).
5. 복잡도를 센다 — 답의 개수 × 답 하나 만드는 비용이 하한이다.

### 가지치기의 종류

가능성 판정(현재 부분해가 제약을 이미 어김 — N-Queen에서 같은 열·대각선), 한계 판정(남은 최선을 더해도 지금까지의 최고를 못 넘음 — 분기 한정), 대칭 제거(같은 답을 순서만 다르게 만드는 가지 — 조합에서 `i >= start`), 방문 표시(그래프에서 돌아온 곳). 가지치기 하나가 실행 시간을 자릿수 단위로 바꾼다.

### 꼬리 재귀와 자바

마지막 동작이 자기 호출뿐인 꼬리 재귀는 반복문으로 기계적으로 바뀐다. 자바 컴파일러·JVM은 꼬리 호출 최적화를 하지 않으므로(Kotlin은 `tailrec`) 깊은 재귀는 직접 반복으로 바꿔야 한다. 트리 순회처럼 "자식마다 부르고 결과를 합치는" 재귀는 꼬리가 아니라 명시적 스택이 필요하다.

### 코딩 테스트에서

순열·조합·부분집합 템플릿을 손에 익힌다(조합은 `start`로 중복 제거). "모든 경우"·"가능한 배치"·"최대/최소를 만족하는 조합" 문장은 백트래킹 신호. n ≤ 10~15면 2ⁿ·n!도 된다는 뜻이고, 그 이상이면 DP·그리디를 의심한다. 자바에서 재귀 깊이가 1만을 넘길 가능성이 있으면 스택 크기를 키운 스레드(`new Thread(null, r, "", 1 << 26)`)로 돌리는 관행이 있다.

### 실무에서는

- 재귀는 트리(파일 시스템, 조직도, JSON) 처리에 자연스럽지만, 입력 깊이를 사용자가 정하면(깊게 중첩된 JSON) 재귀 깊이 제한을 둔다 — 공격 벡터가 된다.
- 재귀 함수는 상태를 매개변수로 넘기고 전역·필드를 쓰지 않는다. 테스트와 병렬 실행이 쉬워진다.
- 검색·추천에서 "조합 폭발"이 보이면 백트래킹 + 가지치기가 첫 시도이고, 안 되면 근사·휴리스틱.

### 면접 질문

#### 재귀와 백트래킹은 무엇이고, 백트래킹이 완전 탐색과 다른 점은 무엇인가요?

재귀는 문제를 같은 꼴의 작은 문제로 줄여 자기 자신을 부르는 것으로 종료 조건이 필수이고, 백트래킹은 재귀로 선택지를 하나씩 시도하며 답이 될 수 없는 가지는 더 들어가지 않고 되돌아가는 탐색 방법입니다. 완전 탐색이 모든 경우를 끝까지 만드는 것이라면 백트래킹은 가지치기로 그중 대부분을 중간에 버립니다.
"하나 고르고 나머지는 같은 문제"라는 구조 덕분에 k겹 반복문을 깊이 k의 재귀로 바꿀 수 있고, 되돌리기(선택 취소)가 있어야 다음 선택지가 깨끗한 상태에서 시작됩니다.
예를 들어 N-Queen은 행마다 열을 고르고 같은 열·대각선이면 가지치기해 8-Queen을 수천 번의 시도로 풉니다(8⁸ ≈ 1,600만 대신). 한계는 최악은 여전히 지수 시간이라 n이 20을 넘으면 어렵고, 재귀 깊이가 스택 크기에 묶이며, 되돌리기를 빠뜨리는 실수가 흔하다는 점입니다.

- 오답: "백트래킹은 DFS다" — DFS는 그래프 탐색 순서이고 백트래킹은 해 공간을 탐색하는 방법이다. 백트래킹을 DFS 순서로 구현하는 것일 뿐이다.
- 꼬리: 되돌리기를 빠뜨리면 어떤 버그가 나나요?
- 꼬리: 순열과 조합의 재귀에서 중복을 어떻게 막나요?

#### 재귀로 짠 코드가 큰 입력에서 StackOverflowError를 냅니다. 어떻게 하나요?

먼저 종료 조건이 맞는지(무한 재귀인지)를 확인하고, 맞다면 입력 깊이가 스택 한계를 넘는 것이므로 재귀를 반복문으로 바꿉니다. 꼬리 재귀면 그대로 루프로, 아니면 명시적 `Deque`를 스택으로 써서 같은 순서로 처리합니다.
자바는 꼬리 호출 최적화를 하지 않고 스레드 스택이 기본 수백 KB~1MB라 깊이 수만이면 넘치기 때문입니다.
예를 들어 연결 리스트 순회나 깊은 트리의 DFS는 스택에 노드를 넣고 꺼내는 루프로 바뀝니다. 임시로는 `-Xss`나 큰 스택의 스레드로 돌릴 수 있지만 근본 해결은 아닙니다. 한계는 반복문으로 바꾸면 코드가 길어지고 "돌아올 때 할 일"(후위 처리)이 있는 재귀는 스택에 상태를 함께 넣어야 해서 실수가 늘어난다는 점입니다.

- 오답: "메모리를 늘리면 된다(`-Xmx`)" — 힙이 아니라 스레드 스택(`-Xss`)의 문제이고, 그것도 임시 방편이다.
- 꼬리: 어떤 재귀가 꼬리 재귀이고 왜 반복으로 바꾸기 쉬운가요?

## 개념

그리디는 문제를 단계로 나누고, **각 단계에서 지금 가장 좋아 보이는 것을 고른 뒤 다시 돌아보지 않는다**. DP가 모든 선택을 비교해 저장하는 것과 달리 하나만 고르므로 빠르고 단순하다 — 보통 정렬 한 번 뒤 한 번 훑기(O(n log n)). 문제는 **"지금 최선"이 "전체 최선"이 되느냐**다. 그것이 성립하는 문제(그리디 선택 속성 + 최적 부분 구조)에서만 맞고, 아닌 문제에서는 그럴듯한 오답을 낸다. 그래서 그리디는 알고리즘보다 **"이 기준이 맞다는 증명"이 본체**다.

맞는다고 알려진 대표 문제: 활동 선택(끝나는 시간 순), 최소 신장 트리(크루스칼·프림), 다익스트라(음수 가중치 없을 때), 허프만 코딩, 배수 단위 동전, 분할 가능한 배낭(단위 무게당 가치 순). 틀리는 대표: 0/1 배낭, 일반 단위 동전, 최장 경로.

#### 예시 — 활동 선택(겹치지 않게 가장 많은 회의 고르기)

```java
// 끝나는 시간 순으로 정렬한 뒤, 직전에 고른 회의가 끝난 뒤에 시작하는 것을 차례로 고른다
int maxMeetings(int[][] m) {           // m[i] = {start, end}
    Arrays.sort(m, Comparator.comparingInt(a -> a[1]));
    int count = 0, lastEnd = Integer.MIN_VALUE;
    for (int[] x : m) {
        if (x[0] >= lastEnd) { count++; lastEnd = x[1]; }
    }
    return count;
}
```

#### 작동 과정 — 왜 "빨리 끝나는 것부터"가 맞나(교환 논증)

- 어떤 최적해가 있다고 하자. 그 최적해의 첫 회의를 `A`, 전체에서 가장 빨리 끝나는 회의를 `G`라 하자.
- `G`는 `A`보다 늦게 끝나지 않으므로, 최적해에서 `A`를 `G`로 바꿔도 뒤의 회의들과 겹치지 않는다. 개수는 그대로 → 여전히 최적.
- 같은 논리를 두 번째, 세 번째 회의에 반복하면 "그리디가 고른 순서"와 같은 최적해가 존재한다.
- 결과: 그리디 선택이 최적해의 일부가 될 수 있음을 보였다(그리디 선택 속성). 남은 문제(그 회의 뒤에 시작하는 것들)는 원래와 같은 꼴이다(최적 부분 구조). 이 두 단계가 그리디 증명의 틀이다.

#### 비교 — 그리디와 DP

| | 그리디 | DP |
|---|---|---|
| 단계에서 | 하나 고르고 끝 | 모든 선택을 비교해 저장 |
| 시간 | 대개 O(n log n) | 상태 수 × 전이 |
| 맞는 조건 | 그리디 선택 속성이 증명될 때 | 최적 부분 구조 + 중복 부분 문제 |
| 틀리면 | 그럴듯한 오답(알아채기 어려움) | 상태 정의가 틀리면 답이 안 나옴(알아채기 쉬움) |
| 예 | 활동 선택, 크루스칼, 다익스트라 | 0/1 배낭, LCS, 편집 거리 |

## 왜 나왔나

모든 경우를 보는 것은 느리고 DP도 상태 수만큼 비용이 든다. 어떤 문제들은 구조상 "지금 최선"이 미래를 망치지 않아, 정렬 한 번이면 끝난다는 것이 1950~70년대 스케줄링·네트워크 문제에서 발견됐다(크루스칼 1956, 다익스트라 1959, 허프만 1952). 이론에서는 그리디가 맞는 구조를 매트로이드로 일반화했다. 실무에서는 "빠르고 단순한데 대체로 좋은 답"이 필요할 때 그리디를 근사 알고리즘으로도 쓴다 — 이때는 "맞다"가 아니라 "최적의 몇 % 안"이 보장이다.

## 확인 질문

- 설명해 보기: 그리디가 맞으려면 문제가 갖춰야 할 성질은?
  답: 그리디 선택 속성(지금의 최선 선택이 어떤 최적해의 일부가 됨)과 최적 부분 구조(그 선택 뒤 남은 문제가 같은 꼴). 앞의 것이 핵심이고 교환 논증으로 보인다.
- 다음 상태 예측: 활동 선택을 "가장 짧은 회의부터"로 고르면?
  답: 틀릴 수 있다. 짧은 회의 하나가 긴 회의 두 개의 가운데에 걸쳐 있으면 짧은 것 1개를 고르고 긴 것 2개를 못 고른다. "빨리 끝나는 것부터"만 증명된다.
- 다음 상태 예측: 0/1 배낭(물건을 쪼갤 수 없음)을 "무게당 가치가 높은 것부터"로 채우면?
  답: 틀릴 수 있다. 용량 10에 (무게 6, 가치 60)·(무게 5, 가치 50)·(무게 5, 가치 50)이면 그리디는 60, 정답은 100. 쪼갤 수 있으면(분할 배낭) 그리디가 맞다.

## 심화

### 그리디를 증명하는 두 방법

**교환 논증**: 최적해와 그리디의 첫 선택이 다르면 최적해의 그것을 그리디 선택으로 바꿔도 여전히 최적임을 보인다. **앞서 감(stays ahead)**: 그리디가 k번째 선택까지 어떤 해보다 "뒤지지 않음"을 귀납으로 보인다(활동 선택에서 k번째 회의의 끝 시간이 항상 빠르거나 같음). 코딩 테스트에서는 완전한 증명 대신 "반례를 만들어 보기"로 걸러내되, 안 떠오른다고 맞는 것은 아니다.

### 자주 나오는 그리디 기준

정렬 기준이 곧 알고리즘이다 — 끝나는 시간(구간 스케줄링), 시작 시간(회의실 개수 = 동시에 겹치는 최대), 마감 순(지각 최소화), 비율(분할 배낭), 간선 가중치(크루스칼), 현재 거리(다익스트라 — 우선순위 큐로 "지금 가장 가까운 것"). 두 기준 중 하나를 골라야 하면 두 원소를 바꿨을 때 결과가 어떻게 변하는지(교환)로 판단한다 — "두 수를 이어 붙여 가장 큰 수 만들기"는 `a+b`와 `b+a`를 비교하는 정렬.

### 우선순위 큐와의 결합

"매번 가장 작은/큰 것을 꺼내 처리하고 새 것을 넣는다"는 그리디는 힙(우선순위 큐)이 자연스럽다 — 허프만(가장 작은 둘을 합침), 다익스트라, 작업 스케줄링(가장 빨리 비는 기계에 배정). 정렬 한 번으로 안 되는 이유는 처리 중에 후보가 바뀌기 때문이다.

### 근사로서의 그리디

집합 덮개·외판원처럼 정확한 답이 NP-hard인 문제에서 그리디는 "최적의 ln n배 안"처럼 보장이 있는 근사 알고리즘이 된다. 실무의 배치·추천·캐시 교체(LRU도 그리디)는 대부분 이 자리다.

### 코딩 테스트에서

"최대 개수·최소 비용" + n이 10⁵ 이상(DP 표를 못 만듦) + 정렬하면 풀릴 것 같음 → 그리디 후보. 기준을 정했으면 작은 반례를 2~3개 만들어 본다. 반례가 나오면 DP로. 구현은 정렬 + 한 번 훑기 또는 힙.

### 실무에서는

- 작업 스케줄러(스레드 풀에 가장 오래 기다린 작업 먼저), 로드밸런서(연결 수가 가장 적은 서버), 캐시 교체(LRU)는 전부 그리디이고, "최적"이 아니라 "충분히 좋고 빠름"이 목표다.
- 그리디로 만든 배치·할당 결과가 이상하면 반례 상황인지 본다. 그때는 작은 범위만 DP·완전 탐색으로.

### 면접 질문

#### 그리디 알고리즘은 무엇이고, 언제 쓸 수 있으며, DP와 어떻게 다른가요?

매 단계에서 지금 가장 좋아 보이는 선택을 하고 되돌아보지 않는 방법으로, 그 선택이 어떤 최적해의 일부가 된다는 그리디 선택 속성과 남은 문제가 같은 꼴이라는 최적 부분 구조가 성립할 때만 맞습니다. DP는 모든 선택을 비교해 저장하므로 그런 보장 없이도 맞지만 상태 수만큼 느립니다.
그리디가 맞는 문제는 정렬 한 번에 O(n log n)으로 끝나므로, 맞는지 증명(교환 논증)이 되면 그리디, 안 되면 DP입니다.
예를 들어 회의를 최대한 많이 잡는 문제는 끝나는 시간 순 그리디가 맞고, 0/1 배낭은 무게당 가치 순 그리디가 틀려 DP가 필요합니다. 한계는 그리디가 틀릴 때 그럴듯한 오답을 내서 테스트 몇 개로는 못 걸러내고, 기준을 잘못 잡으면(가장 짧은 회의부터) 같은 문제에서도 틀린다는 점입니다.

- 오답: "그리디는 DP의 빠른 버전이라 대충 맞는다" — 조건이 성립하지 않으면 틀린 답이다. 근사 보장이 있는 경우만 "대충 맞음"이라 할 수 있다.
- 꼬리: 활동 선택에서 "빨리 끝나는 것부터"가 맞다는 것을 어떻게 보이나요?
- 꼬리: 다익스트라는 왜 음수 가중치에서 틀리나요?

#### 회의실 하나에 회의를 최대한 많이 배정하는 문제와, 모든 회의를 하려면 회의실이 최소 몇 개 필요한지는 각각 어떻게 푸나요?

첫 문제는 끝나는 시간 순으로 정렬해 직전 회의가 끝난 뒤 시작하는 것을 차례로 고르는 그리디이고, 둘째는 시작 시간 순으로 정렬해 최소 힙에 진행 중인 회의의 끝 시간을 넣고, 새 회의가 힙의 최소 끝 시간 이후면 그 회의실을 재사용(교체)하고 아니면 새 회의실을 더하는 그리디로, 힙의 최대 크기가 답입니다.
첫 문제는 "빨리 끝나는 것을 고르면 남는 시간이 최대"라는 교환 논증이, 둘째는 "어느 순간 동시에 겹치는 회의 수가 곧 필요한 회의실 수"라는 하한이 그리디와 일치하기 때문입니다.
둘 다 O(n log n)입니다. 한계는 회의마다 가치가 다르거나(가중 구간 스케줄링) 회의실마다 제약이 다르면 그리디가 틀려 DP나 이분 매칭으로 가야 한다는 점입니다.

- 오답: "둘 다 끝나는 시간 순으로 풀면 된다" — 둘째 문제는 시작 시간 순으로 훑어야 동시 겹침을 정확히 센다.
- 꼬리: 회의에 가치가 있을 때 최대 가치 배정은 어떻게 푸나요?

## 개념

피보나치 `fib(n) = fib(n-1) + fib(n-2)`를 재귀로 짜면 `fib(5)`가 `fib(3)`을 두 번, `fib(2)`를 세 번 계산한다 — n이 40이면 10억 번 호출이다. **같은 작은 문제를 반복해서 푼다**는 것이 문제이고, 답을 **표에 적어 두고 두 번째부터는 꺼내 쓰면** n번의 계산으로 끝난다. 이것이 동적 계획법이다. 적용 조건은 둘 — 큰 문제의 최적해가 작은 문제들의 최적해로 구성되고(**최적 부분 구조**), 작은 문제가 **겹친다**(중복 부분 문제). 겹치지 않으면 분할 정복(병합 정렬)이고, 최적 부분 구조가 없으면 DP로 못 푼다.

푸는 순서는 정해져 있다. ① **상태**를 정한다 — "어디까지 결정했을 때의 답"을 `dp[i]`(또는 `dp[i][j]`)로. ② **점화식** — `dp[i]`를 더 작은 `dp[…]`들로 어떻게 만드나. ③ **초기값** — 가장 작은 문제의 답. ④ **채우는 순서** — 작은 것부터(상향식 표) 또는 필요할 때 재귀 + 저장(하향식 메모이제이션). ⑤ 답이 어느 칸에 있나.

#### 예시 — 계단 오르기(한 번에 1칸 또는 2칸, n칸까지 가는 방법 수)

```java
// 상태: dp[i] = i번째 칸에 도달하는 방법 수
// 점화식: dp[i] = dp[i-1] + dp[i-2]  (마지막 걸음이 1칸이었거나 2칸이었거나)
// 초기값: dp[0] = 1, dp[1] = 1
int ways(int n) {
    int[] dp = new int[n + 1];
    dp[0] = 1; dp[1] = 1;
    for (int i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
    return dp[n];
}
```

#### 작동 과정 — 메모이제이션이 호출을 줄이는 모습

- 하향식 `fib(5)`: `fib(4)`를 부르고, 그 안에서 `fib(3)`, `fib(2)`, `fib(1)`까지 내려가 답을 `memo`에 적으며 올라온다.
- `fib(4)`가 끝나고 `fib(5)`가 `fib(3)`을 부른다 → `memo[3]`에 있다 → 즉시 반환. 재귀 없음.
- 결과: 각 `fib(k)`는 딱 한 번만 실제로 계산된다. 호출 수 2ⁿ → n. 상향식은 같은 것을 재귀 없이 표를 0부터 채워 얻는다.

#### 비교 — 하향식과 상향식, DP와 이웃들

| | 하향식(메모이제이션) | 상향식(타뷸레이션) |
|---|---|---|
| 형태 | 재귀 + 저장 | 반복문으로 표 채우기 |
| 계산 범위 | 필요한 상태만 | 모든 상태 |
| 위험 | 재귀 깊이(스택) | 채우는 순서를 틀리면 안 채워진 칸 참조 |
| 언제 | 상태 공간이 크고 일부만 쓸 때, 점화식이 복잡할 때 | 대부분. 메모리 최적화(직전 행만 유지)도 쉬움 |

| | 분할 정복 | DP | 그리디 |
|---|---|---|---|
| 작은 문제가 겹치나 | 아니오 | 예 | — |
| 매 단계 선택 | 전부 풀어 합침 | 전부 비교해 최선 저장 | 하나만 고르고 안 돌아봄 |
| 예 | 병합 정렬 | 배낭, LCS, 최단 경로(벨만-포드) | 동전(특정 단위), 활동 선택 |

## 왜 나왔나

1950년대 Bellman이 다단계 결정 문제(매 단계 선택이 다음 단계에 영향)를 풀며 "현재 상태에서의 최적 결정은 그 이전 결정과 무관하게 정해진다"(최적성 원리)를 정리했다. 이름의 "dynamic"은 시간에 따른 단계를, "programming"은 계획표(table)를 뜻한다 — 코딩과 무관하다. 컴퓨터에서는 "재귀의 중복 계산을 표로 없앤다"는 기법으로 정착했고, 문자열 비교(diff, 편집 거리), 자원 배분(배낭), 경로(최단·최장), 확률(HMM), 파싱(CYK)에 두루 쓰인다.

## 확인 질문

- 설명해 보기: DP가 되려면 문제가 갖춰야 할 두 성질은?
  답: 최적 부분 구조(큰 문제의 최적해가 작은 문제의 최적해로 구성됨)와 중복 부분 문제(같은 작은 문제가 반복됨). 후자가 없으면 저장할 이득이 없다.
- 다음 상태 예측: 동전 [1, 5, 10]으로 12원을 만드는 최소 개수를 "큰 동전부터"(그리디)로 하면? DP로는?
  답: 그리디 10+1+1 = 3개, 정답. 하지만 동전 [1, 6, 10]으로 12원이면 그리디 10+1+1 = 3개, 정답은 6+6 = 2개. 그리디는 단위에 따라 틀리고 DP `dp[x] = min(dp[x-c]) + 1`은 항상 맞는다.
- 다음 상태 예측: `dp[i][j]`가 `dp[i-1][j]`와 `dp[i][j-1]`에 의존하는데 `j`를 바깥 반복문으로 돌리면?
  답: `dp[i][j-1]`은 채워져 있지만 `dp[i-1][j]`는 같은 `j` 열의 이전 행이라 순서에 따라 아직 안 채워졌을 수 있다. 의존하는 칸이 먼저 채워지도록 `i`를 바깥으로 돌린다(또는 둘 다 작은 것부터).

## 심화

### 상태를 잡는 법

"결정을 하나 내렸을 때 남는 문제가 원래와 같은 꼴인가"를 묻는다. 남는 문제를 구별하는 최소한의 정보가 상태다. 배열 문제는 `dp[i]` = i번째까지 고려한 답, 두 수열이면 `dp[i][j]`, 배낭이면 `dp[i][w]` = i번째 물건까지 고려하고 용량 w일 때 최대 가치. 상태에 "마지막에 무엇을 골랐나"가 필요하면 차원을 하나 더한다(`dp[i][last]`). 상태 수 × 전이 비용이 시간 복잡도다.

### 대표 문제의 점화식

| 문제 | 상태 | 점화식 |
|---|---|---|
| 0/1 배낭 | `dp[i][w]` | `max(dp[i-1][w], dp[i-1][w-wt[i]] + val[i])` |
| 최장 공통 부분 수열 | `dp[i][j]` | 같으면 `dp[i-1][j-1]+1`, 아니면 `max(dp[i-1][j], dp[i][j-1])` |
| 최장 증가 부분 수열 | `dp[i]` = i로 끝나는 LIS 길이 | `max(dp[j]) + 1` for `j < i, a[j] < a[i]` (O(n²), 이분 탐색으로 O(n log n)) |
| 편집 거리 | `dp[i][j]` | `min(삽입, 삭제, 교체)` |
| 격자 경로 수 | `dp[r][c]` | `dp[r-1][c] + dp[r][c-1]` |

### 메모리 줄이기

`dp[i]`가 `dp[i-1]`만 보면 배열 전체 대신 변수 둘로(피보나치). 2차원에서 이전 행만 보면 행 하나(배낭은 `w`를 큰 쪽부터 돌려 한 줄로). 상태 수가 10⁷을 넘으면 메모리 제한을 먼저 계산한다.

### 답 복원

최적값만이 아니라 "무엇을 골랐나"가 필요하면 각 칸에서 어느 전이를 택했는지 저장해 두고 끝에서 거꾸로 따라간다. LCS의 실제 문자열, 배낭에 넣은 물건 목록이 그렇다.

### 코딩 테스트에서

"최대·최소·경우의 수" + "앞의 선택이 뒤에 영향" + n이 10³~10⁴면 DP 신호. 점화식이 안 보이면 작은 예를 손으로 표를 그려 본다. 배열 인덱스 `i-1`, `i-2`의 초기값·범위 체크가 가장 흔한 실수. 자바에서는 `int` 오버플로(경우의 수는 `long` 또는 모듈러)를 조심한다.

### 실무에서는

- diff 도구·맞춤법 교정·유사도 검색이 편집 거리·LCS다.
- 재고·예산 배분, 광고 슬롯 배치는 배낭 변형. 상태 수가 폭발하면 근사(그리디·휴리스틱)로 바꾼다.
- 캐시(메모이제이션)는 DP의 실무 얼굴 — 함수가 순수하고 입력이 반복되면 `Map`이나 `@Cacheable`.

### 면접 질문

#### 동적 계획법이란 무엇이고, 어떤 문제에 적용할 수 있나요?

큰 문제의 답을 더 작은 같은 꼴 문제들의 답으로 만들 수 있고(최적 부분 구조) 그 작은 문제들이 반복해서 나올 때(중복 부분 문제), 작은 문제의 답을 표에 저장해 한 번만 계산하는 방법입니다. 상태를 정하고 점화식과 초기값을 세운 뒤 작은 것부터 채우거나(상향식) 재귀에 저장을 붙입니다(하향식).
재귀의 중복 계산이 지수 시간을 만드는데, 서로 다른 작은 문제의 수는 다항 개이므로 저장하면 그만큼으로 줄어들기 때문입니다.
예를 들어 피보나치는 2ⁿ 호출이 n번의 계산이 되고, 0/1 배낭은 `dp[i][w]` 표로 O(nW)에 풉니다. 한계는 상태 수가 너무 크면(연속값, 순열 상태) 메모리·시간이 안 되고, 최적 부분 구조가 없는 문제(최장 단순 경로)는 DP로 못 풀며, 상태를 무엇으로 잡을지가 문제마다 달라 그 통찰이 핵심이라는 점입니다.

- 오답: "DP는 재귀를 반복문으로 바꾸는 것이다" — 핵심은 저장(재사용)이고, 재귀에 메모이제이션을 붙인 것도 DP다.

#### 동전 거스름돈을 그리디로 풀면 안 되는 경우와, DP로는 어떻게 푸나요?

동전 단위가 서로 배수 관계가 아닐 때 그리디(큰 동전부터)는 틀립니다 — [1, 6, 10]으로 12원은 그리디 3개(10+1+1), 정답 2개(6+6). DP는 `dp[x]` = x원을 만드는 최소 개수로 두고 `dp[x] = min(dp[x - c]) + 1`을 모든 동전 c에 대해 0원부터 채웁니다. O(금액 × 동전 종류).
그리디는 "지금 최선"이 전체 최선이라는 보장(그리디 선택 속성)이 있어야 하는데 일반 단위에서는 없고, DP는 모든 선택을 비교해 저장하므로 보장이 필요 없기 때문입니다.
[1, 5, 10, 50, 100, 500]처럼 배수 관계면 그리디도 맞아 더 빠릅니다. 한계는 DP의 금액이 10⁹처럼 크면 표를 못 만들어 다른 접근(수학적 성질, 그리디 증명)이 필요하다는 점입니다.

- 오답: "그리디가 맞는지는 예제 몇 개로 확인하면 된다" — 반례가 없다고 증명된 것이 아니다. 배수 관계나 교환 논증으로 증명해야 한다.

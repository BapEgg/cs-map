## 개념

자바로 서버를 만들 때 **매번 반복되는 일을 대신 처리해 주는** 틀(프레임워크)이다. 요청 받기, 객체 만들어 연결하기, DB 접근, 트랜잭션.
개발자는 비즈니스 로직만 쓰고 나머지는 스프링이 맡는다. 대신 스프링이 정한 방식을 따라야 한다.

## 왜 나왔나

2000년대 초 자바 서버 표준(EJB)은 무거운 규격을 따라야 했고 테스트하기 어려웠다. 스프링은 "평범한 자바 객체를 컨테이너가 만들어 연결해 주고(IoC/DI), 트랜잭션·로깅 같은 공통 일은 프록시로 끼워 넣는다(AOP)"는 두 발상으로 가볍게 시작했고, 스프링 부트가 설정을 자동화하면서 자바 백엔드의 기본이 됐다.

이 과목은 스프링 부트 3.x(스프링 프레임워크 6.x, Java 17+, Jakarta EE 9+)를 기준으로 쓴다. 순서는 컨테이너(IoC/DI, 빈 생명주기) → 요청이 지나는 길(MVC) → 끼워 넣기(AOP·프록시, 트랜잭션) → 데이터(JPA 영속성 컨텍스트, N+1) → 테스트다.
